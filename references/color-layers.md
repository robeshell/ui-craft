# 层次配色与去 AI 味

本文件回答的是"颜色放在哪里"，不是"选什么主题色"。项目自己的规范或 tokens 已经规定了颜色分配时，按项目的来，这里的规则只用于规范没覆盖的地方。主题色由品牌决定；这里处理的是页面底、内容表面、区块、图标、状态这些层次上的颜色怎么分配，让界面舒服，并避开 AI 生成页面常见的套路。

## 1. 一个根因：用颜色冒充重要性

大色块背景、每行一个彩色图标底块、渐变首屏，这三种表现看起来不同，根因是同一个：想表达"这块很重要"，但只会用颜色。颜色确实醒目，可一屏里每块都醒目，就等于都不醒目，而且用户会误以为着色的地方可以点、有状态、有含义。

修法也只有一条：重要性靠面积、位置和字重表达，颜色留给含义。含义指的是状态（成功、警告、错误）、交互（主操作、选中、焦点）和品牌识别（固定的一两处）。给一块区域上色之前先问：这个颜色在告诉用户什么？答案是"为了好看"或"为了醒目"，就换成面积、位置或字重。

拿掉一种强调时，不要换上另一种。彩色块换成深色粗描边、彩色标签换成灰色标签，都还是在喊"这里重要"。拿掉之后，这块内容和旁边的内容用同一种表面、同一种文字；它真的更重要，就给它更大的面积或更靠前的位置。

## 2. 表面分层模型

页面上的颜色按层分配，层与层之间只差一到两档明度，靠明度差分区，不靠换色相。

| 层 | 用途 | 浅色模式起始值 | 深色模式起始值 |
| --- | --- | --- | --- |
| 页面底 | 最底层，承载一切 | `#F5F6F8` | `#121417` |
| 内容表面 | 卡片、列表、面板、表格 | `#FFFFFF` | `#1A1D22` |
| 浮起层 | 下拉、气泡、拖拽中的元素 | `#FFFFFF` + 阴影 | `#22262C` + 1px 边线 |
| 遮罩层 | 弹窗、抽屉 | `#FFFFFF` + 更大阴影 + 半透明黑遮罩 | `#2A2F36` + 1px 边线 + 遮罩 |

这套值是临时基线，项目有 tokens 时以项目为准。用它们时注意：

- **浅色模式不要超过三档明度。** 页面底、表面、浮起，够了。再多一档，用户分不出谁在谁上面。
- **深色模式越浮起越亮。** 和现实里的光照一致。深色模式下阴影几乎不可见，用 1px 边线（比表面亮一档）代替阴影表达边界。
- **深色模式不用纯黑，浅色模式不用纯白页面底。** 纯黑配浅色文字会晕，纯白页面底上再放白色卡片就没有层次。
- **中性灰可以带一点品牌色调。** 把品牌色的色相混进灰色，饱和度压到很低，页面会更统一，不会显得死灰。用 `scripts/surfaces.py` 从品牌色生成这套灰阶，它会顺便算好每一档上文字的对比度。
- **文字对比度按实际底色算。** 同一个灰字放在页面底和内容表面上，对比度不同。基线里 `#767676` 在白底上 4.54:1，在 `#F5F6F8` 上只有 4.20:1。

深色模式文字起始值：主要文字 `#F2F3F5`，次要 `#B4B8BF`，辅助 `#969BA3`。三个值在 `#1A1D22` 表面上分别为 15.22:1、8.49:1、6.05:1；辅助文字在最亮的遮罩层 `#2A2F36` 上仍有 4.82:1。

## 3. 颜色预算

一屏里的颜色种类是有预算的：

- **一种强调色。** 用于主操作、选中态、当前项。通常是品牌色，品牌色对比度不够时另设一个操作色。
- **中性灰阶。** 页面底、表面、文字、分隔线，全部来自同一套灰阶。
- **状态色。** 成功、警告、错误，只出现在有状态的地方，并且总有文字或图标陪同。反过来也成立：真正的状态不要在收敛颜色时被一起抹掉。"已满员"、"已过期"、"失败"这类会改变用户下一步动作的状态，保留一种语义色；"余 4 位"这类普通信息用中性色。

超出预算就要说明理由。检查方法很机械：数一下页面上有几种色相。强调色一种，状态色至多三种，其余全是灰。发现第五种色相，先找它服务于什么含义，找不到就并入前四种。

允许的例外：数据可视化里的分类色（按图表规则另算），用户内容里的颜色（头像、封面图、用户自定义标签），品牌要求的固定色彩组合。

## 4. 大面积着色

大面积着色指整条顶栏、整张卡片、整个区块用饱和色或渐变做背景。它把一块区域从页面里"抠"出来，代价是这块区域压过所有其他内容。

| 场景 | 允许吗 | 说明 |
| --- | --- | --- |
| 展示型页面的首屏 | 允许 | 品牌表达是这里的任务 |
| 原生应用的顶栏 | 看平台 | 部分平台惯例允许，内容区不跟着染色 |
| 选中的行、当前的标签 | 允许，但用浅色调 | 表达状态，不是装饰 |
| 仪表盘、后台的页头 | 不允许 | 页头不是任务，一整条品牌色会压过下面的数据 |
| 每张指标卡一种粉彩底 | 不允许 | 指标之间没有"哪个更重要"的信息，颜色在制造假的区分 |
| 内容区底下铺渐变 | 不允许 | 文字对比度没法保证，渐变本身也不表达含义 |
| 空态、引导页的插图区 | 允许，小面积 | 局部，不和内容抢 |

不允许的场景用什么替代：明度分层（第 2 节）加区块标题加间距，就能完成分区。需要一点品牌存在感时，用一条 3px 的强调色竖线或底线，不要染整块。

## 5. 图标底块

"圆角色块上叠一个白色图标"这个样式本身不是错，错在用错地方。它原本用于一种场景：一屏里有一组平级入口，用户要靠图形快速区分，比如消费类 App 首页的宫格。这时每个入口一个色块是在帮用户分辨。

判定：

- **图标是不是用户识别这一项的主要线索？** 不是的话去掉底块，图标用中性灰单线，和旁边文字同一色系。
- **这一组各项是不是平级且需要快速区分？** 是的话可以用底块，但一组内用同一种样式；每个一种颜色是在用颜色预算换噪音。
- **图标出现在列表行、设置项、表格、指标卡里，一律不用底块。** 这些地方用户按文字扫描，图标只是辅助。

替代做法：图标 20 或 24 尺寸，线宽 1.5 到 2，颜色用次要文字色；和文字间距 8，共用一条基线。需要一点区分时，只给图标换色，不给它加底。

## 6. 渐变

渐变只在品牌明确要求时使用，紫色不是默认色。

- 项目有品牌色，就用品牌色的平涂。没有品牌色，用中性灰加一种从内容里来的强调色。宁可没有个性，也不要 AI 个性。
- 渐变可以出现的地方：品牌首屏、图表填充、进度条。不可以出现的地方：文字、按钮、卡片背景、整页背景。
- 评审时看到 `linear-gradient`、`radial-gradient` 或 `bg-gradient-to-*`，先问它服务于什么。答不上来就是要去掉的。

## 7. 有色底上的文字

状态标签、提示条、选中行会用到浅色调底，这是允许的，但有边界：

- **同色相配对。** 浅底配同色相的深字，比如 `#FEF2F2` 底配 `#B91C1C` 字。不要浅底配白字，对比度几乎不可能达标。
- **对比度照常检查。** 浅底上的深字要过 4.5:1，一个色相一个色相地算，不要按感觉。
- **浅底的饱和度要低。** 底色越饱和，文字越难读，区块也越像大色块。起始值：底色明度 95% 以上。
- **同一屏里浅底区块不超过两处。** 超过两处，它们就变成了第 4 节说的粉彩卡片。

## 8. AI 味特征清单

这些是 AI 生成页面最常见的模式。评审时逐条对照，设计时逐条避开。

| 特征 | 怎么识别 | 修法 |
| --- | --- | --- |
| 紫蓝渐变背景 | `from-purple-*`、`to-indigo-*`、`#7C3AED` 到 `#2563EB` 一类 | 换成页面底加内容表面的明度分层 |
| 彩虹指标卡 | 每张指标卡一种颜色的浅底或顶边 | 全部改成同一种表面色，用数字大小和位置区分主次 |
| 图标底块 | 每行左侧一个圆角色块加白图标 | 去底块，图标用次要文字色单线 |
| 渐变文字 | `bg-clip-text` 配渐变 | 用单色，靠字号和字重 |
| 发光阴影 | 彩色的、扩散很大的 `box-shadow` | 换成小而中性的阴影，或者不用阴影 |
| 到处磨砂玻璃 | 每个容器都有 `backdrop-blur` | 只保留真正浮在内容上的那一层 |
| 深蓝底配霓虹色 | 深色模式用 `#0F172A` 一类的深蓝，强调色用高饱和青紫 | 中性深灰分层，强调色降一档饱和度 |
| 所有东西都是药丸形 | 按钮、卡片、输入框、标签全是最大圆角 | 按组件角色分档圆角 |
| 每个区块一个 emoji | 标题前面加 emoji 当图标 | 去掉，或换成同一族的线性图标 |
| 装饰性的大数字 | 超大字号的统计数字配一句无意义说明 | 数字尺寸跟它在任务里的重要性走 |

## 9. 评审时的检查顺序

1. 数色相。超过"一种强调色加灰阶加状态色"，先记下多出来的每一种在哪里。
2. 找大面积着色。每一处问它表达什么含义，答不上来就归入待改。
3. 找图标底块和渐变。按第 5、6 节判定。
4. 查有色底上的文字对比度，逐对算。
5. 查表面分层：页面底、表面、浮起层是不是各差一档明度，深色模式是不是越浮越亮。

写问题时给出位置、现在的色值、对比度数字和替代值，不写"配色不舒服"。
