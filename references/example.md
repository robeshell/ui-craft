# 示例：客服工单处理页

这是一个完整的推演，展示 SKILL.md 五个步骤如何落到一个具体页面。页面是虚构的，用来说明方法，不是模板。遇到"所有模块等大"、"像原型"、"主次不清"的页面时，可以按同样的思路走一遍。

## 起点

一个 Web 后台的客服工作台首页，桌面端 1280 宽。原稿是两行三列共六张等大的白卡片，每张都有 1px 灰描边、8px 圆角、同样的标题字号：

```
┌────────────┐ ┌────────────┐ ┌────────────┐
│ 今日统计    │ │ 待处理工单  │ │ 我的工单    │
│ 新增 128    │ │ #4821 登录… │ │ #4790 退款… │
│ 已解决 96   │ │ #4820 支付… │ │ #4788 发票… │
│ 平均 3.2h   │ │ #4819 账号… │ │             │
└────────────┘ └────────────┘ └────────────┘
┌────────────┐ ┌────────────┐ ┌────────────┐
│ 公告        │ │ 快捷操作    │ │ 最近动态    │
│ 系统维护…   │ │ [新建][转派]│ │ 张三 处理了…│
│ 假期排班…   │ │ [导出][设置]│ │ 李四 关闭了…│
└────────────┘ └────────────┘ └────────────┘
```

用户的抱怨是"看着像原型，找不到重点"。

## 第 0 步：任务模式

这是"页面设计 / 重排"。从代码里能读到：项目有品牌蓝 `#2563EB`，已有按钮组件，文字没有规范，只有零散的 `font-size`。用户没锁定布局，只要求保留品牌蓝和现有功能。

一个需要问的问题：客服在这页主要是"接下一条工单"还是"看团队今日概况"？用户回答是前者，主管才看概况。这个答案决定了整个页面的主体，所以值得问。

## 第 1 步：任务 → 视觉权重

用户在此页要完成：**找到并接下一条最该处理的工单。**

| 优先级 | 内容 | 为什么 |
| --- | --- | --- |
| P0 | 待处理工单列表 | 任务本身 |
| P1 | 每条工单的优先级、等待时长、类型 | 决定先接哪一条 |
| P2 | "接单"操作 | 完成任务的动作 |
| P3 | 我的工单 | 已接的，次要关注 |
| P3 | 今日统计 | 主管视角，客服偶尔看 |
| P3 | 公告、最近动态 | 偶尔看 |
| 合并 | 快捷操作 | 新建、转派、导出属于列表的行内或工具栏操作，不需要独立卡片 |

映射到空间：

- 待处理列表占主列约 70% 宽度，首屏至少显示 8 条。
- 统计压缩成列表上方一行三个数字，高度和分量都不超过列表。
- 我的工单、公告、动态收进右侧 30% 窄栏，字号降一档，颜色降一档。
- 接单按钮放在每行尾部，用品牌蓝，是页面上唯一的实心蓝色元素。
- 新建工单放在列表工具栏右侧，转派和导出收进行内的更多菜单。

检查：去掉颜色只看面积，主列列表占了大半个屏，右栏是配角。阅读顺序从统计一行扫到列表第一条，再到行尾的接单。成立。

## 第 2 步：信息关系 → 空间

**亲密性。** 工单是连续、结构相同、逐行扫描的对象，改成列表行，不做卡片。统计三个数字是一组，共用一条基线。右栏三个模块各是一组，用区块标题和 32px 区块间距分开，不加描边。

**对齐。** 列表行建立五条对齐线：

| 列 | 对齐 | 宽度 |
| --- | --- | --- |
| 优先级标记 | 左，固定 | 24 |
| 编号 + 标题 | 左，弹性 | 剩余 |
| 类型 | 左，固定 | 96 |
| 等待时长 | 右，等宽数字 | 88 |
| 操作 | 右，固定 | 96 |

等待时长用等宽数字并右对齐，"2h 15m"和"14h 03m"不会让列漂移。标题超长时单行省略，鼠标悬停显示完整内容。

**重复。** 右栏三个模块用同一套"区块标题 + 列表行"结构。统计数字和列表里的等待时长用同一个等宽数字角色。

**对比。** 页面上只有两种强调：优先级"紧急"用红色标记加"紧急"文字，接单按钮用品牌蓝实心。其余全部是中性色。原稿里六个同样大小的黑色标题全部降为区块标题角色。

**分区表达。** 页面底 `#F5F6F8`，主列和右栏用白色表面。不加描边，靠明度差和 24px 间隔分区。列表行之间用 `#E5E7EB` 细分隔。

## 第 3 步：产品表达

这是一个作业工具，用户一天要在这里接几十条工单。选三个贯穿的特征：

1. **稳定的数字。** 统计、等待时长、工单编号全部等宽数字，位置不跳动。
2. **克制的颜色。** 品牌蓝只出现在接单按钮和当前选中行的左侧 3px 指示条上。状态色只用于优先级标记。
3. **紧凑的行。** 行高 44px，一屏能看 12 条，扫描效率优先于留白感。

装饰决策：无卡片阴影，无渐变，圆角统一 8px（按钮）和 12px（表面）。空态用一行文字"暂无待处理工单"加一个 48px 线性图标，不放插画。

## 第 4 步：规范表

项目原来没有文字规范，按临时基线建一套，标注待项目确认：

| 角色 | 字号 | 字重 | 行高 | 颜色 | 溢出 |
| --- | --- | --- | --- | --- | --- |
| 页面标题 | 20 | 600 | 1.25 | `#1A1A1A` | 不截断 |
| 区块标题 | 14 | 600 | 1.3 | `#5C5C5C` | 不截断 |
| 列表主文字 | 14 | 500 | 1.4 | `#1A1A1A` | 单行省略，悬停显示全文 |
| 辅助文字 | 13 | 400 | 1.4 | `#767676` | 单行省略 |
| 统计读数 | 28 | 600 | 1.1 | `#1A1A1A` | 等宽数字，预留 5 位 |
| 等待时长 | 14 | 400 | 1.4 | `#5C5C5C` | 等宽数字，右对齐，预留 "99h 59m" |
| 按钮标签 | 14 | 500 | 跟随 32px 按钮 | 白 / `#1A1A1A` | 不换行 |

色彩角色：

| 角色 | 色值 | 对白底对比度 |
| --- | --- | --- |
| 主操作 | `#2563EB`（品牌蓝，保留） | 白字在其上 5.17:1 |
| 主要文字 | `#1A1A1A` | 17.4:1 |
| 次要文字 | `#5C5C5C` | 6.69:1 |
| 辅助文字 | `#767676` | 4.54:1 |
| 紧急标记 | `#DC2626` + 文字"紧急" | 4.83:1 |
| 分隔线 | `#E5E7EB` | 装饰用 |

对比度用 `scripts/contrast.py` 逐对算过，全部按完整精度判定。

间距角色：页面边距 32，主列与右栏间隔 24，容器内边距 20，区块间距 32，行高 44，行内列间距 16，图标和文字间距 8。

## 第 5 步：实查记录

- 页面 / 状态：工作台首页，正常态、空态、12 条和 200 条数据
- 视口：1280 和 1024，浏览器缩放 100% 和 125%
- 代码版本：feat/workbench-relayout

| 项目 | 状态 |
| --- | --- |
| 规则已定义 | 是，见上表 |
| 代码已实现 | 是 |
| 渲染已检查 | 是，1280 和 1024 下截图核对 |
| 交互已验证 | 是，检查了接单按钮的悬停、按下、加载和失败提示 |
| 用户已接受 | 待确认 |

未覆盖：1024 以下的响应式折叠未做，右栏在 1024 下已经偏窄，需要下一步决定是折叠还是改为底部标签。深色模式未做。

## 改了什么

- **主体**：六张等大卡片 → 待处理列表占主列，首屏可见 12 条。解决"找不到重点"。
- **分组**：统计从卡片压缩为一行数字，快捷操作合并进列表工具栏和行内菜单，右栏三个次要模块共用一套结构。解决"像原型"。
- **表达**：品牌蓝只用于接单和选中，等宽数字让列表不跳动，去掉所有描边和阴影改用明度分区。
- **规范**：新增文字、色彩、间距角色表，标注为临时基线。

## 从这个例子里能带走什么

- 问对一个问题（"客服还是主管视角"）比做三个方案更有效。
- "合并"是一种优先级。快捷操作卡片消失了，功能没有少。
- 只有两种强调的页面比有六种强调的页面更容易找到重点。
- 规范表的"溢出"列和"预留位数"是防止上线后跳动的关键，不要省。
- 写清楚"未覆盖"比宣称全部完成更有用。
