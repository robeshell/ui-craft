# 常见页面的成熟版式

本文件给的是先验，不是模板。成熟产品对每一类页面都有一套通用结构，用户已经习惯了，照着做就是"标准"，偏离它才需要理由。AI 生成页面爱把每个模块做成一张卡摆成网格，根本原因是没有这套先验。

用法：第 1 步确定用户任务之后，先在这里找页面类型，拿到标准结构，再按任务决定哪块是主体。结构来自这里，主次来自任务，两者不冲突。项目自己的布局规范和组件库优先于本文件。

每种页面写四项：任务、标准结构、主体、AI 版本常见错误。成熟参考列的是公开的设计体系，用来对照，不要求照搬其视觉风格。

## Web 后台

后台的共同骨架：左侧或顶部导航，内容区限制最大宽度，页头一行（标题、面包屑、主操作），下面才是内容。内容区用页面底加白色表面分区，不给每个区块加描边。

### 工作台首页

- **任务**：一个具体岗位的人每天打开它，看今天要处理什么，然后去处理。
- **标准结构**：页头（标题、日期或问候、一个主操作）→ 概览，不能比主体重 → 主列放待办或进行中的事项列表，占大部分宽度 → 右栏放次要信息：动态、公告、快捷入口，字号和对比降一档。
- **主体**：待处理事项列表。用户每天在这页做的事就是从这里挑一条去处理。
- **AI 版本常见错误**：六到八张等大卡片铺成网格；统计数字做成最大的卡片抢主体；每张卡一种颜色；欢迎语加插画占掉首屏。
- **成熟参考**：Ant Design Pro 的工作台页，Shopify 后台首页。

### 查询列表页

- **任务**：在大量记录里找到目标，批量处理或进入单条。
- **标准结构**：页头（标题、新建按钮）→ 筛选区：常用条件一行，展开更多 → 表格工具栏：结果数、批量操作、列设置、导出 → 表格：固定列宽的对齐线，数字右对齐等宽，状态用点加文字，行尾操作列 → 分页固定在底部。
- **主体**：表格。筛选和工具栏是为它服务的，不能比它显眼。
- **AI 版本常见错误**：每条记录做成一张卡片；表格上方放四张统计卡把表格挤出首屏；每行一个彩色状态药丸；操作按钮全部实心。
- **成熟参考**：Ant Design Pro 的查询表格页，Shopify Polaris 的 Index page，Arco Design Pro 的列表页。

### 详情页

- **任务**：看清一条记录的全部信息，做一两个针对它的操作。
- **标准结构**：页头：返回、标题（记录名或编号）、状态、主操作在右侧 → 摘要区：几个关键字段一行 → 分组信息：按业务含义分成几个区块，标签左、值右或标签上、值下，一致即可 → 关联列表：这条记录下的子项，用表格或列表 → 操作日志放最后。
- **主体**：摘要区和第一个分组。用户进来先确认"是这条吗"，再看细节。
- **AI 版本常见错误**：所有字段平铺成一张大表；每个分组一张带阴影的卡；操作按钮散落在各分组里；状态用大色块横幅。
- **成熟参考**：Ant Design Pro 的基础详情页和高级详情页，Shopify Polaris 的 Detail page。

### 表单页

- **任务**：填完一组信息并提交，尽量不出错。
- **标准结构**：单列，不要两列并排 → 按业务含义分组，组间用标题和间距分开 → 标签在输入框上方，必填标记统一 → 说明文字放在输入框下方，只在需要时出现 → 提交和取消固定在底部，主操作在右。长表单分步骤，顶部显示进度。
- **主体**：输入区。标题、说明、装饰都不能比输入框显眼。
- **AI 版本常见错误**：两三列并排导致视线来回跳；每个字段一张卡；说明文字比标签还大；提交按钮做成整行渐变。
- **成熟参考**：Ant Design Pro 的基础表单和分步表单，Shopify Polaris 的 Form layout。

### 分析看板

- **任务**：看趋势、比数字、发现异常。
- **标准结构**：页头带时间范围选择 → 一行核心指标，数字加同比，等宽数字 → 主图表占宽，一到两个 → 次级图表并排，同高 → 明细表在最下。
- **主体**：主图表。指标行是它的摘要，不能比它高。
- **AI 版本常见错误**：指标做成彩色大卡；六张小图表等大铺满；每张图一种配色；图表用渐变填充。图表本身的颜色按数据可视化的规则另算。
- **成熟参考**：Ant Design Pro 的分析页，Grafana 的仪表盘布局。

### 设置页

- **任务**：找到一项设置并改掉它。
- **标准结构**：左侧分类导航（账号、通知、安全……）→ 右侧当前分类的表单，单列 → 每项设置一行：名称和说明在左，控件在右 → 危险操作单独一组放最后，红色只用在这里。
- **主体**：当前分类的设置列表。
- **AI 版本常见错误**：每项设置一张带阴影的卡；分类做成顶部大标签；每行左侧一个彩色图标底块。
- **成熟参考**：GitHub 仓库设置页，Apple 系统设置的分组列表。

### 处理页

- **任务**：一条一条地处理排队的事项，比如审批、工单、审核。
- **标准结构**：左侧队列列表，窄，显示优先级和等待时长 → 右侧当前事项的详情和处理操作 → 处理完自动跳下一条。也可以是列表页加抽屉。
- **主体**：右侧当前事项。左侧列表只是导航。
- **AI 版本常见错误**：队列做成卡片网格，每条都要点进去再返回；处理按钮和详情分离；优先级用五种颜色。
- **成熟参考**：邮件客户端的三栏布局，Zendesk 的工单视图。

### 空态与引导

- **任务**：告诉用户这里为什么是空的，下一步做什么。
- **标准结构**：居中，一个简单图形或没有图形 → 一句话说明状态 → 一个主操作按钮。首次使用的引导可以多一两句说明，不超过三行。
- **主体**：那个按钮。
- **AI 版本常见错误**：大幅插画；三步流程图；多个按钮；用假数据填充代替空态。

## 移动端

移动端的共同骨架：顶部导航栏（标题、返回、一个操作）→ 内容区 → 底部标签栏或底部主操作。内容区用分组列表，不用卡片网格。iOS 和 Android 各有原生模式，项目用哪个平台就按哪个平台的惯例。

### 移动端列表页

- **任务**：扫描一列条目，选一条进去。
- **标准结构**：顶部导航栏，可带搜索 → 可选的筛选条，横向滚动 → 列表行：左侧可选缩略图或图标，中间标题加一行说明，右侧状态或箭头 → 下拉刷新，上滑加载。
- **主体**：列表行。
- **AI 版本常见错误**：每条一张带阴影的卡片，卡片之间留大间距；行内塞四五个字段；每行左侧一个彩色图标底块。
- **成熟参考**：Apple HIG 的 Lists，Material 3 的 Lists。

### 移动端详情页

- **任务**：看清一条内容，做一个操作。
- **标准结构**：顶部导航栏 → 头部：标题、关键信息、状态 → 分组信息，每组一个小标题 → 主操作固定在底部，不随内容滚走。
- **主体**：头部和第一组信息。
- **AI 版本常见错误**：主操作埋在内容中间；信息全部平铺没有分组；顶部放大色块横幅。
- **成熟参考**：Apple HIG 的 Navigation 和 Toolbars，Material 3 的 Bottom app bar。

### 底部标签页

- **任务**：在三到五个顶级入口之间切换。
- **标准结构**：底部标签栏，三到五项，图标加文字，当前项用强调色 → 每个标签是独立的导航栈。
- **主体**：当前标签的内容，标签栏只是导航。
- **AI 版本常见错误**：六个以上标签；标签栏做成悬浮胶囊；当前项用大色块。
- **成熟参考**：Apple HIG 的 Tab bars，Material 3 的 Navigation bar。

### 移动端表单与流程

- **任务**：在小屏上完成一次输入或一个多步流程。
- **标准结构**：一屏一件事，多步流程分页 → 输入框全宽，标签在上 → 键盘弹出时内容可滚动，主操作不被遮挡 → 下一步或提交固定在底部。
- **主体**：当前这一步的输入区。
- **AI 版本常见错误**：一屏塞完所有字段；提交按钮被键盘挡住；步骤指示器占掉四分之一屏。
- **成熟参考**：Apple HIG 的 Text fields，Material 3 的 Text fields。

### 个人中心

- **任务**：看自己的状态，进入账号相关的设置和记录。
- **标准结构**：顶部：头像、名字、一两个关键数字 → 分组列表：订单或记录类入口一组，设置类入口一组，每行一个图标加文字加箭头 → 退出登录放最后。
- **主体**：分组列表。头部只是身份确认。
- **AI 版本常见错误**：头部做成大面积品牌色或渐变；入口做成宫格，每个一种颜色；数字做成大卡片。
- **成熟参考**：主流电商和支付 App 的"我的"页面结构，Apple HIG 的 Grouped lists。

## 怎么用这份文件

1. 第 1 步写完"用户在此页要完成什么"之后，找到对应的页面类型，拿到标准结构。
2. 按任务确认主体。标准结构告诉你区块顺序，任务告诉你哪块最大。
3. 项目已有的布局规范、组件库和现有页面优先。它们和这里不一致时，按项目的来。
4. 页面不属于上面任何一类时，回到第 1 步的方法自己推导，不硬套。
5. 生成的页面和标准结构一致，就不需要再"设计"。这时候的精致来自对齐、间距、文字角色和状态，不来自新的布局创意。
