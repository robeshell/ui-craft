# 视觉决策规则

本文件是通用方法的细节参考，结合教程、组件实践与迭代经验整理。场景示例用于解释取舍，不是默认主题或统一参数。来源与校正依据见 [来源](sources.md)。

## 1. 内容与视觉动线

先区分页面的任务入口、主要内容、必要操作与辅助信息。根据用户的操作顺序排列，而不是先画一组卡片再填内容。

- 让页面主题、当前状态和下一步操作容易定位。同一信息不必在导航标题、卡片标题和大标题中重复。
- 同类内容维持相同结构和对齐线；表格、列表、时间线和地图按内容关系选择，不能为了形式而新增字段。
- 找到局部重点后，减少周围竞争性的强调。标题不需要同时变大、加粗、变色、加图标和加底块。
- 用户已锁定的品牌元素可作为局部例外，其风格不必扩散到每一个辅助控件。
- 做新产品规划时可借助用户故事、旅程或竞品比较；已经明确问题的局部改版不强制补这些产物。调研方法不能替代真实调研证据。

## 2. 文字：以角色定义整套属性

规范表至少包含「角色、字体、字号、字重、行高、颜色、溢出处理」。只有一串字号不足以构成文字规范。

先选择必要角色，例如页面标题、内容标题、正文、辅助信息、操作标签；测量读数或展示型大标题有明确目的时另设角色。页面不必使用规范里的全部档位。

判断方法：

- 中文界面优先检查实际中文字体的字面、字重和混排，不用英文短词代替长中文标签验收。
- 正文和辅助内容保持稳定；用少量字重区分层级，避免同屏随意出现很多相近字号和粗细。
- 起始字号从项目现有文字角色与目标平台获取；无现成基线时，用代表性真实内容制作小样比较。不要把其他项目的字号表移植为默认值。
- 行高根据阅读长度、字形与用途设置。多行说明需要呼吸空间，按钮单行标签不应机械套用长文章行距。不要把「行高」误写成额外的行间距。
- 中文常规正文不做装饰性加宽字距。数字、单位和标点保持合理邻近关系；更新频繁的数字可检查等宽数字特性是否能减少跳动。
- 发生拥挤时先查信息量、对齐、容器内边距和可换行空间。不要直接压成小字，也不要用超大字弥补没有层级。
- 用真实长度检查：一行／多行标题、长公司名或地点、数字位数变化、缺失可选字段、系统字体放大。关键操作与错误信息不能因截断消失。
- 原生文本遵循用户字体设置，容器允许增长；不能通过反向缩小、固定物理像素或裁切抵消系统放大。

## 3. 单位与跨平台

| 场景 | 应区分的内容 |
| --- | --- |
| Web | CSS 像素、浏览器缩放、响应式宽度、字体设置；设备像素不是布局单位 |
| Android | dp 布局、sp 字体；屏幕密度与字体缩放分别影响结果 |
| HarmonyOS | vp 布局、fp 字体；按实际组件/API 和系统字体设置验证 |
| iOS | point 布局、文本样式／Dynamic Type、Safe Area；导出倍率属于资源交付 |

教程的 @1×／@2×／@3× 用于理解逻辑尺寸和资源倍率；不能把三倍截图中的文字像素数直接当成应用字号。不同平台同数值不保证字面和基线一致。

用目标设备的逻辑尺寸做设计。屏幕变宽时优先让内容区伸缩或重排，不自动将整页文字、图标和间距等比放大。状态栏、手势区和键盘按运行环境处理，不能从历史机型表抄成永久常量。具体平台 API 和当前设计要求需查对应官方文档。

## 4. 色彩：语义与对比度同时成立

先定义用途，再挑颜色：品牌识别、主操作、主要文字、次要文字、辅助信息、表面、分隔、成功／警告／错误。避免每个页面各选一组近似灰色。

- 品牌色不必承担所有功能。亮品牌色可保留为识别色，同时另设满足文字对比度的操作色。
- 状态用现有文字、图标或形状共同表达；颜色不能是唯一线索。不要把警示红用于普通装饰。
- 灰色层级通过明确色值管理，避免页面再叠透明度后失去可读性。占位提示也属于可读文字。
- 测试真实色对。渐变、照片、阴影和透明色需按文字实际覆盖区域检查；一个色标通过不代表整片背景通过。
- 普通文字通常以至少 4.5:1 检查；只有满足标准定义的大号文字才可使用 3:1，不能按“看起来很大”自行归类。必要控件轮廓、状态指示和信息图形以 3:1 检查相邻颜色。
- 纯装饰分隔线不一定需要 3:1；如果这条线是识别控件的唯一边界，就不能再把它视为装饰。禁用控件存在标准例外，仍需辨认其用途。
- 比值判定使用完整精度，不把 4.49 四舍五入成 4.5 后判为通过。
- WCAG 是检查依据之一；色对达标不等于整应用通过无障碍认证。APCA 可辅助研究，不能宣称已经正式取代 WCAG 2.x。

## 5. 布局：亲疏、对齐、容器

为页面边距、容器内边距、组内间距、组间间距分别赋予角色，复用项目尺度。建立新尺度时按内容密度选择少量有规律的档位，不要求边线、描边和光学校正都使用同一倍数。

- 同组信息距离小于组间距离；分区标题通常更接近它所统领的内容。不要把所有间距都设成一个数。
- 建立少量连续对齐线：标题起线、正文起线、数值列、尾部操作列。同级内容不因装饰随意左右漂移。
- 容器表示独立对象、可操作区域或需要隔离的内容；普通字段不必各有一张卡。
- 信息连续的列表可用行、留白与细分隔。卡片布局适用于独立对象，不能因喜好一律禁用或一律套用。
- 圆角按组件角色统一。嵌套圆角需结合边距保持自然，不把按钮、头像、卡片和弹层全部做成同样的药丸形。
- 阴影用于表达悬浮和遮挡关系；不要把阴影当作每个模块的默认装饰。
- 密度用任务效率和可读性判断：不能为了首屏多放几条而裁掉必要信息，也不能通过大面积空白掩盖信息组织问题。

## 6. 图标：外框一致还不够

确定同一功能图标族，统一轮廓／填充风格、线宽、端点、转角和细节复杂度。品牌插图与功能图标可以各有风格，但要明确角色边界。

- 先核语义是否容易识别，再检查小尺寸清晰度；图形不能只因好看而改变功能含义。
- 同一网格中的圆、方、三角和斜向图形，其视觉重量不同。检查有效面积和重心，必要时做少量光学校正，不能只按边界框机械居中。
- 用实际展示尺寸检查描边和细节，不能只看放大矢量稿。避免拉伸位图或混用不同来源但外框相同的图标。
- 图标视觉大小与触控区分别定义。Android 通常需要至少 48dp 的触控目标；不要通过相邻热区重叠实现表面达标。其他平台按目标规范和任务环境确认。
- 有文字的图标按钮应保持图文间距和共同基线；没有可见文字时提供准确的可访问名称。

## 7. 组件、状态与流程

把重复出现的视觉决策定义成组件。至少检查实际存在的默认、按下、选中、禁用和异步状态；有鼠标交互才要求悬停，不能把网页 hover 当作手机唯一反馈。

组件规范应描述尺寸／内边距、文字角色、图标、颜色、边界、状态变化、内容增长和可访问性。必要时用少量代表性组件验证规则，再扩展到页面。

原型沿真实流程连接：触发条件 → 输入 → 状态变化 → 成果 → 失败或取消。选中样式不能暗示不存在的功能，静态成功图也不能充当实现证据。动效用于表达状态和空间关系；以平台反馈为起点，检查可中断性和减少动态效果设置，不从教程的动画下拉菜单推导出整应用的动效时长。
