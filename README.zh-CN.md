# UI Craft

[![npx skills add robeshell/ui-craft](https://img.shields.io/badge/npx-skills%20add%20robeshell%2Fui--craft-CB3837?logo=npm&logoColor=white)](#使用方法)

[English](README.md) · 中文

给 Claude Code、Codex 这类 coding agent 用的 UI 设计 skill。它给 agent 装一套产品设计师的判断力，专管功能型界面：后台、工作台、工具、App 页面。

它不是"把页面做漂亮"，而是让 agent 在动手改样式之前先回答一个问题：**用户来这页是要做什么？** 视觉权重、分组、颜色和细节都从这个答案推出来。

## 功能

- **主次来自任务。** 页面哪块该占主导，由用户的任务决定，不由模块数量决定。八个模块不会变成八张等大的卡片。
- **克制。** 两条硬规则优先于其他一切。页面已经能用，回复就是"不需要改"，不制造 diff。项目自己的规范（`DESIGN.md`、`AGENTS.md`、`CLAUDE.md`、tokens、组件库）高于 skill 的规则，除非用户明说可以打破。
- **对照优化。** 用户只说"优化一下"时，把页面和这类页面的标准结构逐项对照，按影响排序，只改前面几处。
- **标准版式。** 十三种常见页面（工作台、查询列表、详情、表单、看板、设置、处理页、空态，以及五种移动端页面）的成熟结构和 AI 版本常见错误。
- **颜色只留给含义。** 表面分层模型、颜色预算（一种强调色、灰阶、状态色），以及 AI 味特征清单：紫色渐变、彩虹指标卡、图标底块、发光阴影、满屏灰药丸。
- **诚实的验收。** 对比度按完整精度算，不凭感觉。交付分开写明"规则已定义、代码已实现、渲染已检查、交互已验证、用户已接受"。
- **两个脚本。** `contrast.py` 算 WCAG 对比度，支持透明色合成；`surfaces.py` 从品牌色生成浅色和深色模式的中性灰阶。

它不做展示型页面，不从零配主题色，也不决定功能范围。它只管界面，功能来自用户的需求。

## 使用方法

一条命令装到 Claude Code 和 Codex：

```bash
npx skills add robeshell/ui-craft -g -a claude-code -a codex -y
```

以后用 `npx skills update` 更新。手动安装：克隆仓库后把目录复制到 `~/.claude/skills/ui-craft` 或 `~/.codex/skills/ui-craft`。

Claude Code 里用 `/ui-craft` 调用，Codex 里用 `$ui-craft`，或者直接描述问题。提到布局、主次、颜色、间距、"像原型"、"有 AI 味"的请求会自动触发。

```text
/ui-craft 帮我优化一下这个页面
/ui-craft 这个页面有点 AI 味，颜色太花
/ui-craft 看看 SettingsScreen.kt 有什么视觉问题
/ui-craft 用 Vue 写一个订单列表页
```

agent 会先判断请求属于哪种模式（局部修正、页面设计、对照优化、规范整理、评审、无需改动），只做那么多。

## 方法论

**第 0 步，判断模式，读约束。** 已有品牌、规范文件、真实内容、目标平台。然后是两条硬规则：不为了优化而优化；项目规范高于本 skill。

**第 1 步，从任务推导视觉权重。** 写一句"用户在此页要完成 ____"。把内容分成 P0 持续关注、P1 判断依据、P2 主要操作、P3 其他，再映射到面积、位置、对比度和留白。常见页面从 `references/patterns.md` 拿标准结构。

**第 2 步，用信息关系组织空间。** 亲密性、对齐、重复、对比，按这个顺序。先归组，再选容器。连续同构的内容用列表行，独立对象用卡片。一个重点只用一种强调。

**第 3 步，建立产品表达。** 挑两三个贯穿页面的视觉特征，说清各自服务什么。装饰有规则：阴影给浮起层，渐变只在品牌要求时用，颜色只放在有含义的地方。

**第 4 步，落到细节。** 文字角色含字号、字重、行高、颜色和溢出行为。对比度按实际底色算。图标、热区、圆角、间距角色、组件状态。没有规范的项目有一套标注为"临时基线"的起始值。

**第 5 步，实际验收并交付。** 在目标视口用真实内容和状态检查。写明渲染了什么、没渲染什么、还有什么没覆盖。

完整方法、判定表和示例见 [SKILL.md](SKILL.md) 和 `references/`。
